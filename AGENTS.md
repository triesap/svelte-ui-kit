# Agent instructions — svelte-ui-kit

This is the standalone public `svelte-ui-kit` repository, a source-first
TypeScript CLI and authored registry for SvelteKit. All content is repository-
relative and self-contained. Do not add external coordination paths, operator
secrets, runtime state or private workspace references.

## Read the context for the task

Start with [task routing](docs/agents/README.md). Application adoption uses
[getting started](docs/getting-started.md) and shared public reference; repository
maintenance uses the relevant deep contracts and owning tests. Read this file,
current Git status and closer instructions before edits. Do not require blanket
reading of historical records or create a new ledger/status/API database.

Actual scripts/pins live in package.json; registry/manifests own item/export
inventory, schemas own formats, authored types own APIs, and native producer
inputs own reproducibility. Docs state guarantees; investigate code disagreement
instead of silently weakening the contract.

## Preserve the product boundary

Generated Svelte/TS/plain CSS belongs to the application. No styled kit runtime,
Tailwind/CSS-in-JS, React compatibility, online registry, auto-install/merge/force,
extra unscoped APIs or primitive/identity/state clones. Bits owns complex
interaction; native elements remain appropriate for simple components.

Keep actual native types/unions, bindings, refs, snippets and event cancellation.
Reject unsupported render hooks rather than accepting and dropping them. Preserve
SSR/hydration and request-local semantic state. Distinct Alert Dialog remains
primitive-backed; portal themes/clipping/CSP and native reset/callback limits
stay explicit. Do not patch installed packages, loosen pins, suppress compiler/
accessibility failures or disable SSR to pass.

Keep explicit requests separate from dependency closure, authentic immutable
export/cohort authority and base/local/incoming customization. No-change/dry-run
paths write nothing, including hidden coordination. Real writes revalidate
physical paths and preimages, retain recoverable transactions and publish lock
metadata last. Preserve unmanaged source/CSS/layout/exports and post-crash edits.
Never delete retained journals, falsify hashes or invent requests to trigger cleanup.

## Work and verification

Use the approved task scope, smallest complete changes and coherent verified
commits only when authorized. Protect unrelated work and repository identities.
Push, publication, deployment, credentials/external systems and reference-source
changes need separate explicit authority. Local packing is inspection only.

Follow [verification ownership](docs/agents/testing.md), [contribution policy](docs/CONTRIBUTING.md)
and relevant tests. Prepare native archives before frozen strict installation;
keep shared fixture/compiler/package/native writers serial. Use actual runner
semantics and strict browser diagnostics. Independent acceptance, when required,
uses a separate reviewer; implementation self-review does not grant acceptance.

Review final diffs/status and report changes, actual checks/exits, limitations,
unrun gates and next work. Configured CI is not executed evidence; historical
qualification is not fresh verification. Keep generated outputs and local logs
outside tracked source. Publication and unspecified extension prerequisites
remain explicit in the [product contract](docs/agents/product-contract.md).
