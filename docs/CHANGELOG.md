## Unreleased — local 0.2.0

- Breaking canonical project/lock format 1 requires an explicit SvelteKit, Astro
  or library target. Targetless format 1 and old format 2 are refused. New
  project-config/install-lock schema IDs distinguish these formats; durable
  journals independently use format 3. Keep the previous binary and full evidence
  for reviewed clean-copy adoption and consistent rollback.
- Canonical discovery, package-indexed native evidence and one typed async
  preparation path replace superseded compatibility entry points. Transaction
  effects have their own module owner; published catalog/asset identity is stable.
- SvelteKit layouts require modern `$props()`/`@render` child rendering, including
  legitimate aliases. Astro slots and library stylesheet roles remain distinct.

- Stronger light-surface control boundaries and readable info/success text defaults,
  with unchanged token APIs and ordinary customization-preserving update plans.

- Explicit Astro and standalone Svelte-library generation, target-bound lock and
  recovery metadata, native layout/CSS integration, and independently installed
  generated/packed consumers with strict checking, SSR and hydrated controls.
- Source-first TypeScript CLI with bundled registry/schema/contracts, explicit
  info/init/view/add/sync/doctor commands, read-only plans and guarded writes.
- Complete current component catalog, including distinct Alert Dialog; shared
  identity stays native and RouterLink is an optional Anchor recipe.
- Application-owned generated Svelte/TypeScript/plain CSS, customizable tokens,
  truthful three-way reconciliation/cohorts and interruption-safe recovery.
- Authenticated local native dependency reproduction, explicit application-owned
  archive installation and source-independent local CLI packaging.
- Current installation, styling, upgrade, recovery and component guidance, plus
  maintenance contracts, CI/documentation/package checks and bounded provenance.
- Dual MIT/Apache-2.0 licensing and pinned formatting tooling.

See [compatibility](reference/compatibility.md) for tested pins and native,
browser, filesystem and contrast limits. The publication/extension boundary
remains explicit; no unapproved additional component APIs are delivered.
