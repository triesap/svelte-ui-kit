# ADR-0006 — Preserve unspecified details as explicit gates

Status: retained original decision for scope/discovery boundaries. Original
schema/exit/marker/ownership choices have now been resolved in executable contracts;
completed scheduling is historical, not current maintenance policy.

## Decision and retained rationale

Separate confirmed product guarantees from details that were not supplied.
Inspect actual roots, conventions, toolchain and scripts; use authored types,
manifests and versioned schemas for resolved choices rather than inventing
published schema URLs or claiming speculative APIs are approved.

Select/combobox/popover/date/higher-level direction still needs exact public
inventory, values/search/forms/focus/snippets, locale/timezone/serialization,
styling and qualification contracts before implementation. A complete original
generator/catalog does not mean those extensions were delivered. Available
upstream exports and reusable infrastructure alone do not approve new kit APIs.
See the current [scope contract](../agents/product-contract.md#extension-and-release-boundary).

## Consequences

Ordinary technical choices can use repository evidence inside approved scope.
Speculative new intent requires explicit approval and a durable contract; plans
cannot silently supply missing user requirements or broaden delivery claims.
Publication/name/publisher prerequisites and unsupported platform/native behavior
remain explicit. No issues, release, tag or extension implementation is authorized
by retaining this rationale.
